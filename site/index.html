KEYHSRP의 preempt는 장애 전환 옵션이 아닙니다. 전환은 HSRP가 기본으로 하고, preempt는 우선순위가 높은 라우터가 복구된 뒤 Active 자리를 되찾게 해 줍니다.

! OSPF: 와일드카드는 서브넷 마스크의 반전
router ospf 1
 network 10.0.0.0 0.255.255.255 area 0
!
interface Gi0/0
 standby 1 ip 192.168.1.254      ! PC의 게이트웨이 = 가상 IP
 standby 1 priority 110
 standby 1 preempt

KEYStandard ACL은 출발지만 보므로 목적지 가까이, Extended ACL은 출발지 가까이 둡니다. 모든 ACL 끝에는 보이지 않는 deny any가 있어 permit이 하나도 없으면 전부 막힙니다.

access-list 110 permit tcp 192.168.10.0 0.0.0.255 any eq 443
access-list 110 deny   ip any any log
!
interface Gi0/1
 ip access-group 110 in
!
! PAT: 내부 대역을 외부 인터페이스 IP 하나로
ip nat inside source list 1 interface Gi0/2 overload

KEYInline IPS는 공격 트래픽이 IPS 호스트를 반드시 통과해야 동작합니다. 토폴로지를 분리하고 FORWARD 체인을 NFQUEUE로 넘겨야 drop 룰이 실제로 차단합니다.

# /etc/suricata/rules/local.rules
drop http any any -> $HOME_NET any (msg:"LFI /etc/passwd"; \
  flow:to_server,established; http.uri; \
  content:"/etc/passwd"; sid:1000001; rev:1;)

# 통과 트래픽을 Suricata로
iptables -I FORWARD -j NFQUEUE --queue-num 0
suricata -c /etc/suricata/suricata.yaml -q 0

보안 로그 분석 랩

외부 공격자와 내부망 사이에 IDS/IPS를 두고, 내부 호스트의 로그를 SIEM으로 모으는 구성입니다. 공격 시나리오별로 탐지 룰을 쓰고 차단 여부를 확인했습니다.

  • RULE/etc/passwd 접근, SQL Injection, ICMP를 시나리오별 룰로 탐지
  • DDoSrand-source, smurf, UDP flooding 패턴을 구분해 탐지 조건 작성
  • HIDSVictim · Windows에 에이전트를 설치하고 Wazuh로 이벤트 수집
  • LOGGoAccess로 웹 접근 로그를, Wireshark · tcpdump로 패킷을 교차 확인
  • FWpfSense · ASAv · firewall-cmd 정책을 같은 시나리오로 비교
